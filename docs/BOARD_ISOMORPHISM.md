# Board Isomorphism v0.1

## 为什么值得做

同一个牌面可以有很多写法，但它们是同一个策略问题。不承认这件事，目录就要为每一种写法各存一份：

```text
所有三张翻牌组合          22,100
按牌面等价折叠后           1,755
冗余倍数                   12.6x
```

也就是说，**同样的覆盖率，目录要大 12.6 倍**。越晚做，已经生产的解法越难回填。

## 两条互相独立的等价规则

`board-isomorphism/1.0.0` 只承认两件事，不多也不少：

1. **花色重标号。** 扑克不在乎某张牌是什么花色，只在乎哪些牌同花。`2c 7d Ts` 和 `2h 7s Td` 在 `c→h, d→s, s→d` 下是同一个牌面。
2. **翻牌顺序。** 三张翻牌同时亮出，没有任何行动能区分它们，所以 `2c 7d Ts` 和 `Ts 2c 7d` 是同一个牌面。

**转牌和河牌不可重排。** 它们各自在自己的街道出现，中间隔着下注轮，顺序是有意义的。

规范形式定义为：在全部 24 种花色重标号中，取「三张翻牌排序后 + 转牌 + 河牌」的字典序最小值。排序必须在重标号**之后**做——重标号会改变哪张牌排在前面。

翻前节点没有公共牌，原样保留。翻前不能折叠花色：`AhKh` 和 `AhKs` 不是同一手牌。

## 这条等价假设了什么

**花色重标号只有在节点的其他部分也花色对称时才成立。** 实际上这指的是求解时用的输入范围：一份把红桃和黑桃区别对待的范围，解出来的策略不可迁移。

标准范围是花色对称的，但这是关于**求解**的假设，不是关于牌面的定理。求解质量报告应当写明这一点，`StrategyEvidence` 在应用了置换时也会把这句话带出来。

## 默认关闭，必须显式打开

同构**没有**接进 Matcher 的默认路径。「这两个牌面看起来差不多」式的静默启发式，正是这个项目一直在拒绝的东西。

```python
match_game_spec(observed, catalog)                          # 默认：不认
match_game_spec(observed, catalog, board_isomorphism=True)  # 显式打开
```

关闭时，这个函数输出的每一个字节都和 `gto-match-policy/1.0.0` 一直以来的输出完全相同——有差分测试守着。

新增状态 `isomorphic`，不复用 `exact`。这样任何检查 `status == "exact"` 的既有消费方，在没有被刻意更新之前，对重标号牌面**继续失败关闭**。

| 状态 | 含义 |
|---|---|
| `exact` | 规范化指纹完全相同 |
| `isomorphic` | 除牌面写法外完全相同；结果携带花色置换 |
| `approximate` | 硬维度相同，数值差异在阈值内 |
| `unsupported` | 其余全部情况 |

`exact` 优先于 `isomorphic`。两个目录节点互为等价时返回 `ambiguous`，不按 ID 顺序偷偷选。

## 置换怎么用

匹配结果里的置换是 **观察牌面 → 解法牌面** 的方向，由两次规范化复合而成：观察到规范，再取解法到规范的逆。

```json
"board_isomorphism": {
  "isomorphism_version": "board-isomorphism/1.0.0",
  "suit_permutation": {"c": "h", "d": "s", "h": "c", "s": "d"}
}
```

查询时，你问的组合在**观察牌面的坐标系**里，返回的组合也在观察坐标系里：

```powershell
python -m rivermind_core gto-query pokerstars 100000000002 `
  --before-action 5 --database data/dev.db --catalog solutions/catalog.json `
  --rake-model pokerstars.cash.example --rake-percent 5 --rake-cap-bb 3 `
  --board-isomorphism --combo AhKh --json
```

`StrategyEvidence` 会同时给出 `combo`（观察坐标系，你问的那个）和 `board_isomorphism.solution_frame_combo`（解法坐标系，实际查的那个），映射因此是可审计的，而不是隐含的。

汇总视图不受置换影响：它是对制品自带全部组合的加权平均，重标号只是换标签，不改变这个多重集。

## 索引开销

`SolutionCatalogIndex` 的等价映射是**首次使用时才构建**的：每个解法多一次 SHA-256。从不使用同构的调用方不必为此付费。

## 验证

- **穷举**：全部 22,100 个翻牌，规范化后恰好 1,755 类；每一个都验证了幂等性。
- **随机**：4,000 次随机重标号必须落进同一类。
- **置换代数**：2,000 次随机置换的牌与组合往返，500 次逆元与复合律。
- **默认行为不变**：`tests/test_gto_index.py` 里的线性规格差分测试继续逐字节通过。

## v0.1 限制

- 只处理牌面。**动作线仍要求完全一致**——bet-size translation 是另一个协议，还没做。
- 花色对称的范围假设由报告承担，代码不检查（也无法检查：制品里没有输入范围）。
- 转牌与河牌只做花色重标号，不做任何跑马牌面的等价归并。
- 同构命中不改变质量边界：`usable_for_teaching` 仍然要求 `verified` 标签加通过质量门的签署。
