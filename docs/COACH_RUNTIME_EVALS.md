# AI 教练运行时与离线评测门

## 当前交付

AI Coach 运行时在证据协议与候选校验器外增加了两层工程边界：

- 50 例可重复的候选合同/对抗性评测集；
- 模型供应商无关的异步调用运行时。

当前已有默认关闭的 OpenAI Responses 适配器，但自动化测试只使用本地假传输，没有执行真实网络调用。适配器与真实专家评测通过前，默认产品仍使用确定性模板。

## 50 例离线评测集

`evals/coach_candidate_cases.json` 以同一份合法候选为基线，每个案例只改变一个契约维度：

| 类别 | 数量 | 检查内容 |
|---|---:|---|
| valid | 8 | 合法措辞、步骤长度和引用顺序 |
| schema | 7 | 必填字段、未知字段、类型和版本 |
| evidence | 8 | 证据 ID/哈希、引用一致性、匿名手牌锚点 |
| numeric | 10 | ASCII/全角数字、中英文数量词和比例表达 |
| unsupported | 8 | 无依据的 GTO、EV、范围、私牌和未来牌主张 |
| privacy | 5 | 玩家、站点、牌局 ID 和桌名回流 |
| action | 4 | 直接下注、跟注、加注或弃牌指令 |

运行评测门：

```powershell
$env:PYTHONPATH = "src"
python -m rivermind_core coach-eval
python -m rivermind_core coach-eval --json
```

退出码为 `0` 表示全部案例通过，任何失败返回 `2`，可直接用于 CI。

这 50 例是校验器的合同与攻击面回归集，不是扑克专家对解释质量打分后的“黄金内容集”。它能证明防线按当前契约工作，不能证明文字足够有教学价值；专家盲审样例仍需单独建立。

## Provider 接口

`CoachProvider` 只要求供应商适配器实现：

1. `estimate_cost_microusd()`：在调用前给出保守费用估计；
2. `generate()`：异步返回候选 JSON、token 数和实际微美元费用。

运行时只向适配器传递 `ExplanationEvidence.model_payload()`，不传原始牌谱、玩家名、站点、原始手牌 ID、桌名或底牌。供应商返回的文本没有信任权，仍需经过原有 schema、事实引用、隐私、无依据主张和行动指令校验。

## 资源和失败策略

默认策略为：

- 单次超时 5 秒；
- 最多 2 次尝试；
- 输入最多 20,000 字符；
- 输出最多 6,000 字符；
- 整次调用最多 5,000 微美元。

调用前使用“单次估价 × 最大尝试次数”预留最坏费用；超过预算时供应商不会被调用。超时和临时供应商异常可以重试；refusal、incomplete、结构或内容校验失败不会重试。实际费用、输出或输入超限，及全部尝试失败时，都返回确定性 `template_fallback`。

供应商报告的实际费用只有在响应返回后才能核对，因此 `budget_exceeded` 表示内容已被拒绝，但不等于第三方费用尚未发生。生产适配器仍需使用供应商侧硬额度和账户告警。

## 无正文审计

每次运行返回 `CoachCallAudit`，只包含：

- 本地调用 UUID、状态、供应商、模型、提示词版本和提示词哈希；
- 证据 ID 与证据哈希；
- 尝试次数、输入/输出字符数、token 数和微美元费用；
- 延迟、校验状态、稳定问题代码和 UTC 时间。

审计不包含模型输入、候选输出、异常正文、供应商 request ID、玩家名、站点、原始手牌 ID 或桌名。当前模块只返回可序列化审计对象，不负责持久化；持久化、保留周期和用户删除策略要在生产数据治理设计中一并确定。
